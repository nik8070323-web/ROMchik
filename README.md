# ROMchik — Telegram и Google Drive

Python 3.12+, Aiogram 3. GitHub хранит код; закрытый Google Drive хранит материалы.

## Архитектура

Сохранены команды, кнопки, AdminFilter и FSM. `services/drive.py` заменяет файловый репозиторий.
Drive — источник истины: список и номера восстанавливаются из дерева папок и appProperties,
без SQLite и зависимости от диска Botkeep. Google ID используется в кнопках; входящие ID
проверяются по принадлежности корневой папке. Отдельный локальный backend нужен для старых offline-тестов.
Сетевые операции выполняются в рабочих потоках, HTTP-клиент защищён блокировкой.
OAuth refresh выполняет google-auth; временные ошибки и rate limit повторяются SDK с backoff.
Истёкший/отозванный refresh token требует повторной авторизации владельцем.

## OAuth: личное действие владельца

1. Для первоначальной миграции выполните `rclone config reconnect gdrive:` и войдите в браузере.
   Не публикуйте rclone.conf и не присылайте токены. Существующий remote содержит пустой token.
2. В https://console.cloud.google.com/ создайте отдельный проект ROMchik, включите Google Drive API.
3. Настройте OAuth consent screen и создайте OAuth Client ID типа **Desktop app**.
   Скачайте JSON в `.secrets/client_credentials.json` (каталог исключён из Git).
4. Установите зависимости: `python -m pip install -r requirements.txt`.
5. Минимальный scope `drive.file` работает с файлами, созданными этим OAuth-приложением
   или явно открытыми через Google Picker. Он НЕ даёт доступ ко всем старым вложениям
   только по ID родительской папки. Для существующего дерева, импортированного rclone,
   без реализации Picker требуется scope `drive`:
   `python tools/authorize_drive.py .secrets/client_credentials.json --scope drive`.
   Предпочтительно авторизовать отдельный Google-аккаунт с доступом только к ROMchik,
   чтобы ограничить область доступных данных. Не делайте папки публичными.
   Вариант с `drive.file` требует импорта каждого файла этим же клиентом и отдельной
   проверки видимости существующих папок; автоматически он здесь не включён.
6. Секреты сохранятся только локально в `.secrets/drive.env`, права 0600.
   Добавьте их самостоятельно в Botkeep. Не отправляйте их в чат или GitHub.
7. Для External приложения не оставляйте production в Testing: Google обычно ограничивает
   срок refresh token семью днями. Проверьте статус публикации и требования Google.

Документация scope: https://developers.google.com/workspace/drive/api/guides/api-specific-auth

## Миграция без удаления исходников

Архив ожидается в `aiogram-learning/материалы.zip`; локальные файлы — в `aiogram-learning/лекции/`.

```bash
python tools/migrate_materials.py
# Только после успешной dry-run и проверки manifest:
python tools/migrate_materials.py --apply
```

Скрипт формирует `migration-output/manifest.json` с SHA-256, MD5, размером и исходным путём,
а также staging-каталог. Совпадения исключаются только по SHA-256 внутри одного пути назначения.
Одинаковое задание в разных ПЗ остаётся прикреплено к каждой ПЗ. Разные версии сохраняются;
при конфликте имён локальных источников добавляется суффикс хеша. Неоднозначные пути идут
в `На_разбор`, LR сохраняются отдельно от PZ. `copy --immutable` не удаляет удалённые данные;
существующий путь с другим MD5 останавливает загрузку. `rclone check --one-way` сверяет
содержимое после копирования. При незавершённой загрузке безопасно повторите проверку.

До проверки миграции через постоянный OAuth-клиент не удаляйте локальные исходники.
Список Drive пересобирается при каждом обращении. Незнакомые корневые папки, включая
`На_разбор`, студентам не показываются. `Учебники` ИНО доступны в разделе «Лекции».

## Администратор и студент

`/admin`: выбрать предмет, тип, номер, необязательное название, отправить документ и подтвердить.
После сохранения можно отправить следующий файл в тот же номер или нажать «Готово».
Исходное имя Telegram-документа сохраняется. Для замены отдельного файла используйте
«Управление материалами» → файл → «Заменить». Удаление требует подтверждения и помещает
файл в корзину Drive. После изменения другим администратором нужно повторить выбор.
Студент выбирает предмет, «Лекции»/«Практики», номер и получает все вложения этого номера.

Поддерживаются PDF, DOC, DOCX, XLS, XLSX, PPT, PPTX, TXT, PNG, JPG, JPEG, ZIP.
Облачный Telegram Bot API позволяет боту скачать входящий документ до 20 МБ,
отправить документ до 50 МБ. Более крупные материалы сохраняются в Drive, но бот
сообщит об ограничении отправки. Загрузка и скачивание используют временные файлы,
Drive передаёт данные блоками по 1 МБ. Материалы не публикуются по открытым ссылкам.
Лимиты: https://core.telegram.org/bots/api#sending-files

## Botkeep

Не выключайте текущую версию до проверки новой на отдельном тестовом токене.

1. Python 3.12, зависимости из корневого `requirements.txt`.
2. Команда запуска из корня репозитория: `python aiogram-learning/main.py`.
3. `.env` создайте в `/home/container/.env`. Его путь не зависит от рабочей директории.
   Переменные окружения сервера имеют приоритет; `ENV_FILE` задаёт иной путь явно.
4. Перенесите значения из `.env.example` и локального `.secrets/drive.env`:

```dotenv
BOT_TOKEN=<токен тестового бота, затем рабочего при переключении>
ADMIN_IDS=<Telegram ID администратора,несколько через запятую>
MATERIAL_STORAGE=drive
GOOGLE_DRIVE_ROOT_ID=12nhmLr5SAhwo04TIZNJdIUSDwEtETxiL
GOOGLE_CLIENT_ID=<из своего OAuth-клиента>
GOOGLE_CLIENT_SECRET=<из своего OAuth-клиента>
GOOGLE_REFRESH_TOKEN=<полученный при авторизации>
```

5. Сначала проверьте тестовым ботом чтение импортированных файлов, добавление двух вложений,
   выдачу студенту, замену, подтверждённое удаление, отказ постороннему ID и перезапуск.
6. Только после этого переключайте сервер. Одновременно polling одного токена не запускайте.
   Возврат к старой версии возможен: исходники локально сохранены, история Git не переписана.

Секреты на сервере меняет владелец. Архив для Botkeep должен содержать только актуальное
дерево исходников, без `.git`, `.venv`, `.env`, `.secrets`, staging и учебных документов.
История Git всё ещё содержит документы; обычный source ZIP истории не содержит.
Если Botkeep ограничивает весь clone, а не source ZIP, нужна отдельная согласованная
очистка истории после `git bundle create ROMchik-backup.bundle --all`; force push здесь не выполнялся.

## Проверки

```bash
MATERIAL_STORAGE=local python -m unittest discover -s tests -v
python -m compileall -q aiogram-learning tools
```

Drive-тесты используют подставной API: несколько файлов, изоляция предметов, замена,
конфликт версий, корзина, восстановление каталога, потоковое скачивание и ошибка API.
Это не заменяет проверку настоящих Google/Telegram API после OAuth. Локальные тесты
проверяют AdminFilter и FSM через Dispatcher без обращения к рабочему боту.
